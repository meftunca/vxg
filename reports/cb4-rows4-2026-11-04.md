# Exact CB4 rows4 experiment, 2026-11-04

The opt-in four-row CB4 GEMV launch passes the bounded correctness gates below. It has **no established throughput benefit**: three host-contended pairs are mixed, including an 8.19% regression in the third pair. Default rows2 remains unchanged. No archive, quantization, centroid representation, F32 activation/state arithmetic, sketch, search variant, commit, deletion, or model conversion was introduced.

## Implementation

`native/shaders/vxt_gemv.metal` extracts the existing CB4 per-row body into a shared inline function. The extracted body is text-identical to the retained prior body after removing its row assignment. The ordinary wrapper assigns two rows per threadgroup; the new wrapper assigns four. Each row still has one 32-lane SIMD group, the same cubic decoding, accumulator/FMA/dot sequence, sparse-outlier order and SIMD reduction. No rows8 variant was added.

`native/metal_gemv.mm` reads `VXG_CB4_ROWS4=1` once when creating each `MetalGemvCtx`. Its opaque internal context stores the selection and selected PSO, including the context copied into the generic LLM runner. CB4 alone uses four rows/128 threads when enabled; absent or other values keep two rows/64 threads. Archive and exposed FFI layouts are unchanged. Existing lossless selection is unchanged.

`native/metal_llm.mm` adds optional `VXG_PROFILE_COMMAND` logging after command completion, without splitting encoders or changing their dispatch type. `encode_s` begins **after** `ensure_kv_cap`, before the native CPU embedding copy, and ends just before commit. `wait_s` covers commit through observed completion; `gpu_s` is the command GPU timestamp interval. These exclude Rust caller, streaming, KV-growth and other application work and must not be presented as total CPU attribution. The timing flag was absent in performance pairs.

Experimental opt-in usage (set before model/context construction):

```sh
VXG_CB4_ROWS4=1 vxg-tensor run MODEL.vxt --cb4-greedy --temp 0 --presence-penalty 0 --max-tokens 128
```

Without `VXG_CB4_ROWS4=1`, rows2 remains selected. This compares the two newly compiled contexts; it is not an old-binary full-logit comparison.

## Scheduling attribution and paired diagnostic

One production-schedule rows2 timing sample used the same eight-token CLI prompt. Seven decode commands summed to 1.639843 ms native encode, 58.783174 ms commit/wait, 56.357626 ms command GPU time. Native encode is 2.714% of its measured encode+wait interval. This short diagnostic does not justify a large burst/recovery implementation as the primary optimization, and excludes caller work as described above. No multi-token speculative submission or recovery code was added.

Throughput used the same frozen CLI and artifact, the same 28-token prompt, `--cb4-greedy --max-tokens 128 --temp 0 --presence-penalty 0 --threads 2`, equal streaming, two excluded warmups, then fixed AB/BA/AB order. A is default rows2; B sets only `VXG_CB4_ROWS4=1`. Every pair emitted 128 tokens at position 155 with identical decoded text. CLI performance logs do not contain raw emitted ID arrays; exact ID evidence comes from the separate forty-item run.

| Pair | Order | Rows2 TPS | Rows4 TPS | Rows2 time / rows4 time |
|---|---|---:|---:|---:|
|1|AB|72.191|73.884|1.02345x|
|2|BA|68.760|74.554|1.08427x|
|3|AB|71.398|65.548|0.91807x|

Median paired ratio 1.02345x; median TPS 71.398 versus 73.884. The warmup was 75.68 versus 68.43 TPS, also unfavorable to rows4. The third measured pair regressed 8.19%. These mixed results under heavy host contention do **not** establish a speedup or support default promotion. One-minute load averages recorded during the later stages ranged 91.6–121.5. All monitored runs retained at least 33% free memory and 65.97 GiB disk; no resource abort occurred. Resource sampling is periodic and does not prove an unobserved instantaneous peak. No unrelated process was stopped. Final read-only process inventory found no live model/test executable; all owned harness children had exited successfully.

The experimental opt-in remains available for controlled follow-up; rows2 remains the default. This work establishes a bounded correctness result and a negative/inconclusive performance experiment, not completion of the quality-first maximum-compression/TPS objective.
