numerical acceptance thresholds and target-renegotiation requirements in the earlier

## Acceptance contract

| Metric | Required | Stretch |
| --- | ---: | ---: |
| Allocating CPU encode | >= 4.0 GB/s | Preserve while improving the other metrics |
| Complete encoded bytes / input bytes | <= 0.060000 | Lower if speed survives |
| Safe full-frame CPU decode | >= 12.0 GB/s and >= 1.20x matched LZ4 | >= 15.0 GB/s and >= 1.50x matched LZ4 |

0.06 means 94% size reduction, approximately 16.67:1. GB/s means decimal raw
bytes/second. Twelve is the decode minimum; fifteen is the stretch, not a cap.
The earlier LZ4-relative objectives remain in force.

The user added an energy comparison axis on 2026-09-21: report encode and safe-decode
J/GB against LZ4 and Zstd under the same workload. No absolute energy threshold was
specified. Follow [ENERGY_BENCHMARKS.md](ENERGY_BENCHMARKS.md); absent sensor readings
must remain unavailable rather than being inferred from GB/s.

Retain the M2 Max, single worker, 64 KiB independent blocks, checksum-off timing and
frozen eight-member Q95 manifest. Q95 is its historical name; do not regenerate,
rename or drop members because the ratio target changed. All metrics must hold for
each input with one codec configuration and its corresponding encoded artifact.
Charge headers, dictionaries, padding, exceptions and RAW fallback to ratio.
Charge allocation/selection to encode and parsing/validation to safe decode.
Use cpu_full_frame_preallocated_decode for the primary VXG decode gate; report
cpu_preallocated_decode (prepared directory) separately. Prevalidated replay and
GPU rates remain diagnostic profiles.

## Current evidence against the new target

The existing reports/local-metal-json16-r1.csv contains a five-sample directional
comparison on JSON-16. It is not an all-corpus qualification.

| VXG v2 metric | Measured | Remaining gap |
| --- | ---: | ---: |
| Allocating encode | 2.4865 GB/s | 1.609x to 4.0 |
| Safe full-frame decode | 7.3703 GB/s | 1.628x to 12.0; 2.035x to 15.0 |
| Complete ratio | 0.14650089 | 59.0% fewer encoded bytes to reach 0.06 |

The same run's prepared-directory decode is 7.2802 GB/s. Do not confuse this
profile with the full-frame measurement or combine it with a different artifact.

Re-evaluating the fully charged P5D R9 research packets at 64 MiB gives:

| Family | Research packet ratio | Extra bytes to remove for 0.06 |
| --- | ---: | ---: |
| JSON records | 0.023074254 | 0 |
| Field order / optional / escaping | 0.050617427 | 0 |
| Event / identifiers | 0.078591824 | 1,247,677 |
| Bursty / variable records | 0.083904117 | 1,604,179 |

The per-file ceiling is floor(67,108,864 * 0.06) = 4,026,531 bytes. The 16 MiB
companions have the same pass/fail pattern. JSON and field-order now clear the
ratio-only gate. These are scalar research packets: their reported construction
and reconstruction are far below the requested speeds. No production configuration
currently passes the combined contract.

## Next work

1. Revisit the complete byte decomposition for event and bursty against the new
   6% budget. Identify the dominant model payloads, selectors and residuals and
   quantify a candidate's potential savings before implementing another format.
   Existing source-independent model research is within the continuing project
   scope; routine experiments do not need another permission request.
2. Admit a new candidate only with an explicit generic statistical hypothesis,
   bounded selection/training cost, complete serialized state, byte-exact scalar
   reference and malformed-input checks. Verify on changed names, seeds/order and
   unrelated control inputs. A failed model/layout has to gain new evidence to
   justify another attempt. No field-name, generator-seed or source-path shortcuts.
3. For a representation that fits every member, measure command count and full
   encode/decode costs before optimizing hot loops. Favor fewer reconstruction
   operations and regular bounded output. Bitslicing remains available where
   measured packing or execution benefits justify it; transposition alone does
   not reduce information content.
4. Retain the measured P6P decoder improvement and the current worker-local arena.
   P6E's losing local variants do not establish universal allocator/SIMD limits;
   revisit them only if the new representation materially changes allocation or
   instruction costs. A future arena must be assessed with the public allocating
   encode call still inside the timer.
5. Qualify one integrated candidate with at least seven paired, shuffled processes
   per frozen member, >=0.2-second samples, raw samples and uncertainty estimates.
   Include LZ4 a1/a4 and Zstd -3/1/3 ratio and speed rows. Validate current safe APIs,
   format compatibility and supported backends after relevant code changes.

Real customer-corpus qualification remains outstanding. Reaching the synthetic
triple would justify that next evaluation; it does not itself establish market
adoption. This revision changes the goals, not the measured performance.
